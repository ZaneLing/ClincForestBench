# Visit、检查与问询协议

[English](encounter_protocol.md) | [简体中文](encounter_protocol.zh-CN.md)

医生入口 `/arena` 现在统一覆盖本地已构建的全部数据轨道。进入病例即为 Visit，
先呈现个人信息和首诊描述，医生可立即问询、选择检查，也可随时提交诊断。

## 两个共享库

- `configs/clinical_operations.tsv`：检查/操作基础库，涵盖检验、影像、病理、
  微生物、体格检查、内镜、穿刺取样及专科检查。
- `configs/clinical_inquiries.tsv`：问询基础库，涵盖症状特征、系统回顾、既往史、
  家族史、用药与过敏、生活方式、暴露史、孕产史、儿科史及患者意愿。
- `configs/clinical_aliases.tsv`：来源名称与统一项目之间的显式同义映射。

加载时会加入源数据的独有项目。目前 188 个本地病例形成 **309 个检查/操作项、
397 个问询项**。这是一套覆盖多个专科、可继续扩充的研究目录，不等于穷尽所有
医院的全部医嘱。增加项目时需同时提供稳定 ID 和中英文名称。

所有病例显示相同目录；选择前不显示当前病例是否有结果。后台通过原始证据 ID、
原始事件 ID、明确名称和同义词映射检索结果。未匹配的来源项目保留独立名称；
包含检查结论的叙事标题不会直接成为菜单选项，而会映射到既往报告或病史查阅项。
叙事类粗粒度映射仍需临床复核后才能用于细粒度评分。

数据边界：

- 未记载不等于阴性，不补造患者回答或检查结果。
- DDXPlus 的阴性、默认值、不适用状态保留原始含义。
- 组合检查仅返回已记录分项，并标记不完整组合。
- 重复来源检查保留映射记录及其限定信息；全部证据均无模拟时钟、等待、
  按源顺序解锁或时间评分。源日期仅作为临床病史或来源信息，无源时间线入口。
- Synthea 首诊中的诊断答案不再直接展示，已记录生命体征可通过操作库查询。
- MedAgentBench 的 FHIR 模板明确展示为离线工作流指令。
- 参考诊断、源数据标记为不可参与问诊的事件，以及治疗记录，分别保留在对应
  审计类别，避免当作普通问询结果展示。

## 每步原因、诊断和处方

点击检查或问询后，执行前弹出 5 个原因：支持当前怀疑诊断、鉴别可能诊断、
评估紧急情况、评估严重程度或治疗适用性、其他。必须选择一项；选择“其他”时
必须填写原因。`configs/clinical_reasons.json` 为血常规、心电图、影像、症状、
用药史等提供项目或领域专属的原因文案。还可补充自由说明和当前怀疑的疾病。选项以所选项目生成，不读取
隐藏诊断。它记录的是医生在提示下的自述原因，导出中保留当时全部选项及选择。

若所选检查或问询没有源记录，立即进入 `TERMINATED_MISSING_RESULT`，保存该操作、原因
及此前完整轨迹，并拒绝后续操作。事件标记为 `NOT_RECORDED`，页面明确显示病例已结束。
有记录则立即展示答案或检查结果，医生可继续选择下一项问询或检查。
有记录的阴性或不适用回答不会终止病例。

就诊进行中诊断按钮随时可用，支持疾病目录选择和手动输入，也可修改诊断并继续检查。
有源治疗记录的病例，在诊断后显示可选处方/治疗计划。完成病例需要诊断，不要求
处方；处方仅记录医生计划，不执行真实医嘱。

## 保存、历史、森林和中英文

Case 查看页（`/research`）使用工作台同一套问询库、操作库及源记录映射。
选择病例后直接展示有记录的问题和答案：问询为青绿色，检查/操作为蓝紫色；
桌面双栏展示，手机切换分组。长内容分页阅读，不增加整页滚动。
不展示缺失项、来源 ID、覆盖统计、治疗面板或审计控件；部分检查组合仍标注分项范围。
中英文共用工作台的结果渲染和本地化逻辑。此页只读，不创建或结束就诊，不写入医生轨迹。
`GET /research/encounter-cases` 和 `GET /research/encounter-cases/{case_id}`
沿用研究访问校验；医生工作台的公共目录不暴露病例可用性。

新轨迹使用本地 `data/encounters.db` 持久化；原账户和旧会话继续使用原存储。
事务和客户端事件 ID 防止重复请求产生重复轨迹，API 按登录用户隔离权限。
`/history` 可恢复未结束的就诊、查看已终止病例；刷新和切换语言后可恢复当前记录。
JSON 导出保留原始内容、原因选项、所选原因、假设、诊断、时间和来源映射。

`/forest` 可在研究密钥验证后查看按病例、操作、原因、结果聚合的森林。旧历史
和旧森林可通过 `?mode=classic` 查看。模型 Arena 采用同一病例库并记录分阶段
诊断排序，医生与模型轨迹仍需要按各自交互协议分别分析。

两库、Visit、结果及新工作台均支持中英文。受限病例翻译仍保存在本地，导出不会
自动翻译医生自由文本。运行：

```bash
make audit-encounters
make validate
```

前者输出本地 `data/analysis_runs/encounter_mapping_audit.json`，列出全部病例
映射、首诊/结果/治疗/参考/后续结果类别以及中英文覆盖缺口。词典和字符覆盖检查
不等于医学翻译已人工审定。后者执行测试、前端静态检查和构建。

研究 API：`/research/encounter-mapping` 与 `/research/encounter-forest`。
